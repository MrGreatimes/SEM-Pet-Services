# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing site for Strol (in-home overnight pet sitting and dog walking, Seattle). Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS. Migrated from a plain static HTML/CSS/JS site (previously branded "SEM Pet Services", then "Stroll with Sean") — the migration to Next.js was done specifically to support planned future capabilities (server-side booking logic, dynamic content, an admin area) beyond what static HTML could support.

## Structure

- `app/layout.tsx` — root layout. Loads Fraunces (headings) and Work Sans (body) via `next/font/google`, exposes them as CSS variables consumed by Tailwind's `font-heading`/`font-body`.
- `components/pages/HomePage.tsx` — the homepage (rendered by `app/page.tsx` in English and `app/es/page.tsx` in Spanish; see Languages). Sections in order: hero (full-bleed background photo with a dark scrim), Why Strol (four trust cards), Services (`OfferCard` grid: 4 walk cards, then 3 other-service cards), My Mission (bio + a photo stack, `components/PhotoStack.tsx` (owner's choice 2026-11-12, replacing a carousel with arrows/dots over the photos): 8 photos (Owner and Chloe 1 edit, Oscar, cat 1, Max, Chloe 4, Buddy, Nemo, Kaasie (added 2026-11-13); Nemo is a dog, "Owner and cat 1" is the only cat; order mixes indoor/outdoor) as a pile of tilted prints peeking out behind the top one, nothing drawn over the photos; drag left or right (mirrored, owner request 2026-11-12) = top card tucks to the back when let go after being dragged clear of the card below, springing back if let go sooner (next); left it can be dragged only until its center meets the text column's left edge, right only as far as the finger has room to the screen edge (tuck point capped at half that limit so it's reachable on phones), resisting more the closer it gets (rubber band); on release it swings past its destination by 0.1x the pull, then settles (OVERSHOOT, owner-calibrated); window-level pointer listeners + onDragStart preventDefault so releases are never missed; previous photo only via trackpad swipe right or the focus-only Previous button; a drag never opens the viewer; dots fade in below the pile while swiping and out 1.5s later; Previous/Next buttons only appear on keyboard focus; tapping the top card opens PhotoViewer in gallery mode (swipe or arrow keys through all the photos with a "n / 8" counter, arrow buttons only on mouse devices; closing leaves the last-viewed photo on top of the pile; 2026-11-13); two-column), Service Area, Reviews ("What Clients Say" quote cards from the typed `reviews` array, laid out like Rover reviews (owner's choice): header row with the reviewer's first name and last initial and "<service> for <pet>" plus an optional `date` on the left, and the zoomed pet photo in a circle in the top right corner (a PhotoViewer, so tapping it opens the full photo) (month and year, omitted until known); then the text clamped to 5 lines with a Read more toggle (`components/ReviewText.tsx`, shown only when it overflows). No star ratings (owner's choice; the form doesn't collect them). then a "Leave a Review on Google" button (`googleReviewUrl`); the "Send it to me directly" link to /review was removed 2026-11-12 (owner's choice: steer every review to Google for reach); review text keeps blank-line paragraph breaks (`whitespace-pre-line` in ReviewText)), contact form. Check Availability is the only form on the homepage (owner's choice 2026-10-21: two forms together looked redundant).
- `components/pages/ReviewPage.tsx` (routes `app/review`, `app/es/review`) — standalone review form page (`ReviewForm`) for clients who'd rather not use Google; `noindex` and left out of the sitemap, since clients reach it only from a link Sean texts them (no longer linked from the homepage).
- `components/pages/RatesPage.tsx` (routes `app/rates`, `app/es/rates`; tables are data rows rendered by `RateTable`) — rates & policies page, in order: hero; "What's Always Included" (meet & greet, medication/special needs, daily updates); rates in two columns (Dog Walking first: walk rates (solo only, two columns; group walks discontinued) + add-ons + booking notes; then Overnight: base rate + add-ons; stacked at <=860px); Cat Sitting (visit rates + add-ons) and Off-Leash Dog Park ($45 trip + $20 extra dog) side by side, stacked at <=860px; "Before Your First Booking" checklist; one Policies block (If You Cancel with overnight vs walk terms, If I Cancel, Deposit & Payment, In an Emergency); CTA. Header gets `subnav` (Walking | Overnight | Cat Sitting | Dog Park | Policies; one row on desktop, a 3+2 grid on phones) rendered as a frosted pill under the header pill, with IntersectionObserver scroll-spy; targets use `scroll-mt-[150px]` (184px on phones, where the tab bar is two rows). All sections stay visible (anchors, not tabs) for SEO.
- `app/globals.css` — Tailwind directives plus a few base-layer rules that are impractical to express as utility classes on every element (heading font/weight/color, scroll-margin for anchor targets).
- `components/Header.tsx` — client component (nav toggle, scroll-aware floating/blurred header). Takes a `lightPage` prop for pages with no dark hero behind the header (keeps nav text readable), and an optional `subnav` list of on-page anchor links (used by the rates page). At <=860px the header auto-hides on scroll down and returns on scroll up (always shown near the top and while the menu is open). At all widths, clicking an in-page anchor link hides it until the smooth scroll has finished (150ms with no scroll events, not a fixed timer, so long or upward jumps work), then a scroll up brings it back; pages with a `subnav` (Rates) instead keep it visible through the jump. Because the header tucks away on these jumps, `#services`/`#mission`/`#contact` have `scroll-margin-top: 0` at every width (sections land flush at the top), and arriving on the homepage with a section hash (e.g. from Rates via `/#services`) starts the header tucked away too (2026-10-21). On such arrivals (e.g. the business card QR code -> `/#contact`) the page also snaps back to the section for up to 4s whenever the content above changes size (photos/fonts loading), stopping as soon as the visitor scrolls or touches (2026-11-10). Phone full-screen sections reserve 48px at the top (not 92px) now that the header hides, and use min-h-[100svh] (at least one screen, never a fixed height) so content grows the section on short visible screens instead of spilling into the next one.
- `components/Footer.tsx` — server component, computes the copyright year at render time. Bottom row: favicon + copyright left; right side has round icon-only social links (owner's choice 2026-11-13, to save space; aria-label + title tooltip each) above Privacy Policy (Instagram, Facebook, TikTok, Nextdoor, Yelp, Google; new tab; one-color brand logos from Simple Icons in `lib/brandIcons.ts`) from `lib/social.ts`, and the Strol favicon (`public/images/footer-icon.png`, a copy of `app/icon.png`) beside the copyright line (added 2026-11-13); profiles marked `sameAs` (Instagram, Facebook, TikTok, Nextdoor, Yelp; not the Google share link) are also listed in the homepage LocalBusiness JSON-LD `sameAs`.
- `components/LazyMap.tsx` — client wrapper for the Service Area Google My Maps iframe; mounts it only when scrolled within 600px (IntersectionObserver). Plain `loading="lazy"` still fetched ~500KB of Google scripts during page load and dropped mobile PageSpeed from ~78 to ~60. The header logo uses small copies for the same reason: `public/images/logo-header-primary.png` and `logo-header-reverse.png` (353x144, trimmed from `Strol logo v2 primary/reverse.png`, the v2 logo added 2026-11-05; the header's `aspect-[1745/711]` matches the trimmed artwork). Two stacked `<img>`s crossfade: reverse over the hero; on the scrolled pill or light pages, primary by day and reverse at night (owner's choice 2026-11-05: reverse over the photo, primary when scrolled; the night pill is dark, where primary's navy text is hard to read).
- `lib/booking.ts` — `bookingUrl`, the Square Appointments booking site (Free plan, added 2026-11-12). Only the free 30-min Complimentary Meet & Greet is bookable online, and auto-accept is off, so requests stay pending until Sean accepts. Used by the "Book a Meet & Greet" button at the top of the homepage `#contact` section (above an "or" divider and the Check Availability form, kept as the fallback for out-of-area/unusual requests) and the Rates page CTA (with a "Send me a note" link to `/#contact`). Both open in a new tab. The hero button is also "Book a Meet & Greet" (Square, new tab; owner's choice 2026-11-13, was "Check Availability"). The "Get in touch." button still jumps to `#contact` (so does the business card QR code).
- `lib/styles.ts` — shared class strings (`btnPrimary`, `inputClass`, `labelClass`; field labels are `pointer-events-none` by the owner's choice so only clicking the box focuses a field). `lib/` is in Tailwind's `content` globs; keep it there or these classes get purged.
- `components/OfferCard.tsx` — reusable card for the offer grid; takes per-card `imgClassName` for the couple of photos that need custom `object-position`/`scale` cropping. Desktop: photo above text. At <=860px it turns horizontal (100px square thumbnail left, text right) and the offer grids become one column; desktop-only crops may need a `max-[860px]:` override (the 60-minute walk uses `max-[860px]:object-center`). Walk cards show price only; add-ons live on the Rates page. Each card links (required `href` prop) to its Rates section: walk cards `/rates#walking`, dog park `#dog-park`, cat `#cat-sitting`, overnight `#overnight`; only the title is clickable (`components/OfferTitleLink.tsx`, a client component: underlines on hover only on devices that really hover (`[@media(hover:hover)]:hover:`, so no sticky hover after a tap), and on touch the instant a finger lands (pointerdown, cleared on pointerup/cancel/leave); at <=860px its tap area is the full width of the text column and about 35px tall, via block + py-2/-my-2 so the layout doesn't move); the rest of the card is inert and has no hover lift (owner's choice, 2026-10-21). Tapping the photo opens PhotoViewer; at <=860px its tap area covers the whole left strip of the card (an ::after on the PhotoViewer button via its `buttonClassName` prop, trimmed by the card's overflow-hidden), so a tap just below the thumbnail opens the photo.
- `components/PhotoViewer.tsx` — client component used inside each `OfferCard`, the review card photos and the My Mission photo (the thumbnail's hover zoom is on a wrapper span so it doesn't override a crop `scale-[...]` in `imgClassName`) (optional `sizes` prop for the thumbnail): the thumbnail is a button that opens the full, uncropped photo in a native `<dialog>` overlay (pinch/double-tap zoom on phones, click/scroll-wheel/trackpad-pinch zoom on desktop (a native non-passive wheel listener on the dialog, so a trackpad pinch zooms the photo, not the page), drag to pan; zooming out past 100% rubber-bands (`rubberBand`, floor 55%) and springs back on release (touch; Safari trackpad via its non-standard gesture events), or in Chrome/Edge/Firefox (which never report fingers leaving a trackpad) on the first cursor movement over 3px or click after the pinch, since the cursor stays still during a pinch (that click only springs it back), with a 3s no-activity fallback; closes on a tap outside the photo, the X or Esc; locks page scroll while open). The <dialog> is portaled to document.body and stops React event propagation, because React events bubble through the component tree: before 2026-11-13 touches on the enlarged My Mission photo also dragged the stack behind it, which made the card (and the dialog inside it) inert, so the X stopped working and pinches broke. Gestures are handled on the full-screen container, not just the photo. Optional `gallery` prop. Zooming past 1.5x preloads a full-resolution copy (sizes 400vw) in a hidden img and swaps it in once loaded. Optional `fullImage` prop serves a different file in the overlay: the Dog Park card uses `Ollie 2 full.jpeg`, a copy with the bottom 50px trimmed to remove the Galaxy "AI-generated content" label.
- **Night mode** (added 2026-10-21): automatic, follows the visitor's device (`prefers-color-scheme`; Tailwind `darkMode` is the default `media`). Every color token is a CSS variable (RGB channels) set in `app/globals.css` `:root`, with a night set in the dark media query; `tailwind.config.ts` maps tokens to `rgb(var(--c-x) / <alpha-value>)`. Use `bg-surface` for section backgrounds and `bg-card` for cards/forms, never `bg-white` (white only where it must stay white: hero text, buttons, photo viewer close button). `primary-dark` turns light blue at night, so button hovers use `primary-hover`. Footer and photo viewer backdrop use fixed hex colors so they don't flip. The frosted pill color is `--pill-bg`. Check new UI in both modes.
- `tailwind.config.ts` — design tokens (colors, fonts, radius, shadow, max-width); color values live in `app/globals.css` (see Night mode). Current palette: `primary`/`primary-dark` (blue), `gold`/`gold-light`/`gold-dark` (yellow), `cream`/`cream-alt`, `charcoal`/`charcoal-soft`, plus accessibility tokens `gold-ink` (text on gold-light, 4.98:1; gold-dark there is only 3.4:1) and `field-border` (form field borders, 3:1+ vs white). `app/globals.css` honors `prefers-reduced-motion`.
- `public/images/` — Photos are named by pet (e.g. `Kaasie 1.jpeg`, `Honeybee 2.jpeg`); the owner renamed them from the old numbered files on 2026-09-29. `Owner and Chloe 1 edit.jpeg` is the owner's photo used in the My Mission section and as the OG/JSON-LD image (other `Owner and ...` files are alternates). Note these filenames contain spaces: pass them to `next/image` raw (`src="/images/Owner and Chloe 1 edit.jpeg"`), since pre-encoding them as `%20` gets double-encoded and 404s. `background.webp` is the hero section's full-bleed background image (a CSS background in `.hero-bg`; not preloaded, since the hero heading text, not the photo, is the LCP element and a high-priority preload only competed with it; `Nemo Background.jpeg` is the original it was converted from at WebP quality 80; re-convert if that photo changes). Offer cards (in order): Kaasie 1, Fleia, Honeybee 2, Bunnie 1 (walks), Ollie 2 (dog park), Manu 2 (cat), Biker 1 (overnight). Also the `Strōl`/`Strol` brand asset files (wordmark and icon explorations).

## Deployment

- Hosted on Netlify, connected to the `main` branch of `github.com/MrGreatimes/SEM-Pet-Services`. Netlify auto-detects Next.js and runs `next build`; no manual `netlify.toml` build config was needed at time of migration, but confirm the Netlify site's build command/publish directory match a Next.js app if deploys ever fail after this change.
- The contact and testimonial forms still post directly to Formspree (form ID `xjykrlgr`) as plain HTML forms, no API route. They are client components (`components/ContactForm.tsx`, `components/ReviewForm.tsx`) only for inline validation via `lib/useFormValidation.ts` (validate on blur, re-validate on change once errored, submit does NOT move focus (owner's choice), never reset data on a failed submit, but after a successful submit the form clears itself (setTimeout reset after the browser captures the data, plus a sessionStorage marker checked on mount/pageshow) so "Go back" from Formspree shows empty fields; forms expose `formRef`; permissive email check) and `components/FieldError.tsx` (red text, no icon by the owner's choice; role="alert", linked with aria-describedby; invalid fields get a red border). Required: contact Name + Email; review Name, Pet's Name, Service and Review (the owner made Pet's Name and Service required after first specifying them optional). The review publish-consent checkbox is intentionally optional. Includes a `_subject` hidden field and a `_gotcha` honeypot field for basic spam filtering. This is a likely candidate to move to a Next.js Route Handler later if custom server-side logic (e.g. booking availability checks) gets added.

## Content notes

- Rates, policies (deposit terms, cancellation tiers, add-on fees), and the phone number are real business content provided by the site owner, not placeholders — don't alter the numbers/terms without being asked.
- House style: no em dashes in page copy (previously stripped on request); use commas or "and" instead.
- Brand name is **Strol** (site copy/URLs use the plain spelling, except where the brand name appears in visible marketing copy: the homepage "WHY STRŌL" label, the gold offer box "New to Strōl?" heading and the Rates "Strōl carries general liability insurance" line use the macron by the owner's choice 2026-11-12, drawn by `components/StrolMacron.tsx` (`caps` prop for uppercase labels) (a CSS bar over a plain "o"; Fraunces Bold's own "ō" puts the macron over the "l"); keep titles, metadata, alt text, search-facing text and the legal name "Strol Pet Services" (footer, privacy policy) plain; brand assets in `public/images/` explore a stylized "Strōl" wordmark with a macron-as-bone detail). Do not revisit this naming decision — it was deliberated at length, including a known conflict with an existing Seattle competitor ("Stroll Rover"), and consciously accepted by the site owner.
- Voice: the business is a solo operation, so copy uses first person singular (I / me / my, or "Strol's"), never we / us / our.

## Languages (English + Spanish, added 2026-11-13)

- Every page has a Spanish copy under `/es` (`/es`, `/es/rates`, `/es/privacy`, `/es/review`). The routes in `app/` and `app/es/` are thin wrappers that set metadata (`lib/pageMetadata.ts`: title, description, own canonical, hreflang alternates, Open Graph locale) and render the shared page component in `components/pages/` with `lang="en"` or `"es"`.
- Each page component keeps its text in a `copy = { en: {...}, es: {...} }` object at the top, English and Spanish side by side. **Any copy, price or term change must be made in both languages.** Spanish addresses visitors as "usted" and uses Mexican / Central American wording (owner's choices 2026-11-13): "estadía" (not estancia), "agendar", "cita para conocernos" for the meet & greet, "sin costo" for complimentary, "con licencia, afianzado y asegurado", "fianza de fidelidad", "departamento", "cartilla de vacunación", and gender-neutral phrasing for the reader where possible. Client review quotes stay in English on the Spanish page (owner's choice; a note says so), only the line above each quote is translated.
- `components/LangRoot.tsx` wraps each page: provides `useLang()` to client components (Header, forms, PhotoViewer, PhotoStack, ReviewText) and carries `lang="es"`; server components (Footer) take a `lang` prop. `lib/i18n.ts` has `localePath`, `basePath`, `alternatesFor`. Internal links must go through `localePath(lang, ...)` so Spanish pages link to Spanish pages. Section ids (`#walking`, `#contact`, ...) stay English in both languages.
- Header language switch (`LanguageSwitch` in `components/Header.tsx`): shows the target language ("Español"/"English" pill on desktop, "ES"/"EN" beside the menu button at <=860px; the mobile `--pad`/nav `right` math reserves 84px for the switch + button). It swaps the language in place without a reload (owner request 2026-11-13): it prefetches the other page, `rememberScrollPosition()` (LangRoot) records which heading/paragraph/row is at the top of the screen and its offset, `router.push(href, { scroll: false })`, and LangRoot's layout effect scrolls that same element (same index, since both languages share the layout) back to the same offset before paint. Elements that exist in only one language must carry `data-lang-only` or the matching breaks (e.g. the Spanish reviews and booking notes). Earlier versions used a full reload with a #section, which jumped to the top and scrolled down. It also stores the choice in localStorage (`strol-lang`); an inline script in `app/layout.tsx` sends a visitor who chose Spanish from an English page to its `/es` copy before paint. No automatic browser-language redirect (on purpose, for bilingual visitors and Google).
- Forms on Spanish pages: Spanish labels/errors; Formspree gets `language: Spanish` and "(Spanish)" in the subject. Service option values stay English. Formspree's thank-you page and Square's booking page stay English (the Spanish contact section says the booking page is in English).
- `app/not-found.tsx` picks the language from the URL (`components/pages/NotFoundBody.tsx`). `app/sitemap.ts` lists `/`, `/es`, `/rates`, `/es/rates` with hreflang alternates. The root layout no longer sets a canonical (before 2026-11-13 it leaked "/" into /rates and /privacy).

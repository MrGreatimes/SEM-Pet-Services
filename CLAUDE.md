# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project

Marketing site for Strol (in-home overnight pet sitting and dog walking, Seattle). Next.js 15 (App Router), React 19, TypeScript, Tailwind CSS. Migrated from a plain static HTML/CSS/JS site (previously branded "SEM Pet Services", then "Stroll with Sean") — the migration to Next.js was done specifically to support planned future capabilities (server-side booking logic, dynamic content, an admin area) beyond what static HTML could support.

## Structure

- `app/layout.tsx` — root layout. Loads Fraunces (headings) and Work Sans (body) via `next/font/google`, exposes them as CSS variables consumed by Tailwind's `font-heading`/`font-body`.
- `app/page.tsx` — the homepage. Sections in order: hero (full-bleed background photo with a dark scrim), Why Strol (four trust cards), Services (`OfferCard` grid: 4 walk cards, then 3 other-service cards), My Mission (bio + photo, two-column), Service Area, Reviews ("What Clients Say" quote cards from the typed `reviews` array, laid out like Rover reviews (owner's choice): header row with the reviewer's first name and last initial and "<service> for <pet>" plus an optional `date` on the left, and the zoomed pet photo in a circle in the top right corner (a PhotoViewer, so tapping it opens the full photo) (month and year, omitted until known); then the text clamped to 5 lines with a Read more toggle (`components/ReviewText.tsx`, shown only when it overflows). No star ratings (owner's choice; the form doesn't collect them). then a "Leave a Review on Google" button (`googleReviewUrl`) and a small "Send it to me directly" link to /review), contact form. Check Availability is the only form on the homepage (owner's choice 2026-10-21: two forms together looked redundant).
- `app/review/page.tsx` — standalone review form page (`ReviewForm`) for clients who'd rather not use Google; `noindex` and left out of the sitemap, since clients reach it from the homepage link or a link Sean texts them.
- `app/rates/page.tsx` — rates & policies page, in order: hero; "What's Always Included" (meet & greet, medication/special needs, daily updates); rates in two columns (Dog Walking first: walk rates (solo only, two columns; group walks discontinued) + add-ons + booking notes; then Overnight: base rate + add-ons; stacked at <=860px); Cat Sitting (visit rates + add-ons) and Off-Leash Dog Park ($45 trip + $20 extra dog) side by side, stacked at <=860px; "Before Your First Booking" checklist; one Policies block (If You Cancel with overnight vs walk terms, If I Cancel, Deposit & Payment, In an Emergency); CTA. Header gets `subnav` (Walking | Overnight | Cat Sitting | Dog Park | Policies; one row on desktop, a 3+2 grid on phones) rendered as a frosted pill under the header pill, with IntersectionObserver scroll-spy; targets use `scroll-mt-[150px]` (184px on phones, where the tab bar is two rows). All sections stay visible (anchors, not tabs) for SEO.
- `app/globals.css` — Tailwind directives plus a few base-layer rules that are impractical to express as utility classes on every element (heading font/weight/color, scroll-margin for anchor targets).
- `components/Header.tsx` — client component (nav toggle, scroll-aware floating/blurred header). Takes a `lightPage` prop for pages with no dark hero behind the header (keeps nav text readable), and an optional `subnav` list of on-page anchor links (used by the rates page). At <=860px the header auto-hides on scroll down and returns on scroll up (always shown near the top and while the menu is open). At all widths, clicking an in-page anchor link hides it until the smooth scroll has finished (150ms with no scroll events, not a fixed timer, so long or upward jumps work), then a scroll up brings it back; pages with a `subnav` (Rates) instead keep it visible through the jump. Because the header tucks away on these jumps, `#services`/`#mission`/`#contact` have `scroll-margin-top: 0` at every width (sections land flush at the top), and arriving on the homepage with a section hash (e.g. from Rates via `/#services`) starts the header tucked away too (2026-10-21). Phone full-screen sections reserve 48px at the top (not 92px) now that the header hides, and use min-h-[100svh] (at least one screen, never a fixed height) so content grows the section on short visible screens instead of spilling into the next one.
- `components/Footer.tsx` — server component, computes the copyright year at render time.
- `components/LazyMap.tsx` — client wrapper for the Service Area Google My Maps iframe; mounts it only when scrolled within 600px (IntersectionObserver). Plain `loading="lazy"` still fetched ~500KB of Google scripts during page load and dropped mobile PageSpeed from ~78 to ~60. The header logo uses `public/images/logo-mask.png` (352x144 copy of the 284KB `Strol Pet Services Mono - Black.png`) as a CSS mask for the same reason.
- `lib/styles.ts` — shared class strings (`btnPrimary`, `inputClass`, `labelClass`; field labels are `pointer-events-none` by the owner's choice so only clicking the box focuses a field). `lib/` is in Tailwind's `content` globs; keep it there or these classes get purged.
- `components/OfferCard.tsx` — reusable card for the offer grid; takes per-card `imgClassName` for the couple of photos that need custom `object-position`/`scale` cropping. Desktop: photo above text. At <=860px it turns horizontal (100px square thumbnail left, text right) and the offer grids become one column; desktop-only crops may need a `max-[860px]:` override (the 60-minute walk uses `max-[860px]:object-center`). Walk cards show price only; add-ons live on the Rates page. Each card links (required `href` prop) to its Rates section: walk cards `/rates#walking`, dog park `#dog-park`, cat `#cat-sitting`, overnight `#overnight`; only the title is clickable (`components/OfferTitleLink.tsx`, a client component: underlines on hover only on devices that really hover (`[@media(hover:hover)]:hover:`, so no sticky hover after a tap), and on touch the instant a finger lands (pointerdown, cleared on pointerup/cancel/leave); at <=860px its tap area is the full width of the text column and about 35px tall, via block + py-2/-my-2 so the layout doesn't move); the rest of the card is inert and has no hover lift (owner's choice, 2026-10-21). Tapping the photo opens PhotoViewer; at <=860px its tap area covers the whole left strip of the card (an ::after on the PhotoViewer button via its `buttonClassName` prop, trimmed by the card's overflow-hidden), so a tap just below the thumbnail opens the photo.
- `components/PhotoViewer.tsx` — client component used inside each `OfferCard`, the review card photos and the My Mission photo (the thumbnail's hover zoom is on a wrapper span so it doesn't override a crop `scale-[...]` in `imgClassName`) (optional `sizes` prop for the thumbnail): the thumbnail is a button that opens the full, uncropped photo in a native `<dialog>` overlay (pinch/double-tap zoom on phones, click/scroll-wheel/trackpad-pinch zoom on desktop (a native non-passive wheel listener on the dialog, so a trackpad pinch zooms the photo, not the page), drag to pan; zooming out past 100% rubber-bands (`rubberBand`, floor 55%) and springs back on release (touch; Safari trackpad via its non-standard gesture events), or in Chrome/Edge/Firefox (which never report fingers leaving a trackpad) on the first cursor movement over 3px or click after the pinch, since the cursor stays still during a pinch (that click only springs it back), with a 3s no-activity fallback; closes on a tap outside the photo, the X or Esc; locks page scroll while open). Optional `fullImage` prop serves a different file in the overlay: the Dog Park card uses `Ollie 2 full.jpeg`, a copy with the bottom 50px trimmed to remove the Galaxy "AI-generated content" label.
- **Night mode** (added 2026-10-21): automatic, follows the visitor's device (`prefers-color-scheme`; Tailwind `darkMode` is the default `media`). Every color token is a CSS variable (RGB channels) set in `app/globals.css` `:root`, with a night set in the dark media query; `tailwind.config.ts` maps tokens to `rgb(var(--c-x) / <alpha-value>)`. Use `bg-surface` for section backgrounds and `bg-card` for cards/forms, never `bg-white` (white only where it must stay white: hero text, buttons, photo viewer close button). `primary-dark` turns light blue at night, so button hovers use `primary-hover`. Footer and photo viewer backdrop use fixed hex colors so they don't flip. The frosted pill color is `--pill-bg`. Check new UI in both modes.
- `tailwind.config.ts` — design tokens (colors, fonts, radius, shadow, max-width); color values live in `app/globals.css` (see Night mode). Current palette: `primary`/`primary-dark` (blue), `gold`/`gold-light`/`gold-dark` (yellow), `cream`/`cream-alt`, `charcoal`/`charcoal-soft`, plus accessibility tokens `gold-ink` (text on gold-light, 4.98:1; gold-dark there is only 3.4:1) and `field-border` (form field borders, 3:1+ vs white). `app/globals.css` honors `prefers-reduced-motion`.
- `public/images/` — Photos are named by pet (e.g. `Kaasie 1.jpeg`, `Honeybee 2.jpeg`); the owner renamed them from the old numbered files on 2026-09-29. `Owner and Chloe 1 edit.jpeg` is the owner's photo used in the My Mission section and as the OG/JSON-LD image (other `Owner and ...` files are alternates). Note these filenames contain spaces: pass them to `next/image` raw (`src="/images/Owner and Chloe 1 edit.jpeg"`), since pre-encoding them as `%20` gets double-encoded and 404s. `background.webp` is the hero section's full-bleed background image (a CSS background in `.hero-bg`; not preloaded, since the hero heading text, not the photo, is the LCP element and a high-priority preload only competed with it; `Nemo Background.jpeg` is the original it was converted from at WebP quality 80; re-convert if that photo changes). Offer cards (in order): Kaasie 1, Fleia, Honeybee 2, Bunnie 1 (walks), Ollie 2 (dog park), Manu 2 (cat), Biker 1 (overnight). Also the `Strōl`/`Strol` brand asset files (wordmark and icon explorations).

## Running locally

```
npm install
npm run dev
```

Runs on port 5959 (set in `package.json`'s `dev` script) to match the existing `.claude/launch.json` Browser preview config.

## Deployment

- Hosted on Netlify, connected to the `main` branch of `github.com/MrGreatimes/SEM-Pet-Services`. Netlify auto-detects Next.js and runs `next build`; no manual `netlify.toml` build config was needed at time of migration, but confirm the Netlify site's build command/publish directory match a Next.js app if deploys ever fail after this change.
- The contact and testimonial forms still post directly to Formspree (form ID `xjykrlgr`) as plain HTML forms, no API route. They are client components (`components/ContactForm.tsx`, `components/ReviewForm.tsx`) only for inline validation via `lib/useFormValidation.ts` (validate on blur, re-validate on change once errored, submit does NOT move focus (owner's choice), never reset data on a failed submit, but after a successful submit the form clears itself (setTimeout reset after the browser captures the data, plus a sessionStorage marker checked on mount/pageshow) so "Go back" from Formspree shows empty fields; forms expose `formRef`; permissive email check) and `components/FieldError.tsx` (red text, no icon by the owner's choice; role="alert", linked with aria-describedby; invalid fields get a red border). Required: contact Name + Email; review Name, Pet's Name, Service and Review (the owner made Pet's Name and Service required after first specifying them optional). The review publish-consent checkbox is intentionally optional. Includes a `_subject` hidden field and a `_gotcha` honeypot field for basic spam filtering. This is a likely candidate to move to a Next.js Route Handler later if custom server-side logic (e.g. booking availability checks) gets added.

## Content notes

- Rates, policies (deposit terms, cancellation tiers, add-on fees), and the phone number are real business content provided by the site owner, not placeholders — don't alter the numbers/terms without being asked.
- House style: no em dashes in page copy (previously stripped on request); use commas or "and" instead.
- Brand name is **Strol** (site copy/URLs use the plain spelling; brand assets in `public/images/` explore a stylized "Strōl" wordmark with a macron-as-bone detail). Do not revisit this naming decision — it was deliberated at length, including a known conflict with an existing Seattle competitor ("Stroll Rover"), and consciously accepted by the site owner.
- Voice: the business is a solo operation, so copy uses first person singular (I / me / my, or "Strol's"), never we / us / our.
